---

## 1. 这一步要证明什么

> **博主上传一篇文章，系统能把它变成带租户标记的、可检索的知识切片。**

M0 证明了隔离和契约的基础设施是对的，但它没有任何真实数据流过。M1 是**第一条端到端的数据链路**：
HTTP 请求 → 认证 → 租户上下文 → 素材落库 → 跨服务调用 → 异步任务 → 解析切分 → 向量化 → 写回 chunks。

这条链路一旦跑通，M0 的隔离就从"测试里成立"变成"真实业务里成立"。

---

## 2. 用户故事

1. 博主用邮箱/手机号注册 → 系统自动为他创建一个租户
2. 博主登录 → 创建一个 AI 专家（起个名字）
3. 博主**粘贴一篇文章正文**（或上传 .md/.txt/.docx，或粘贴公众号链接）
4. 博主点"开始构建" → 看到进度条：解析 → 切分 → 向量化 → 完成
5. 构建完成后，数据库里有若干条带正确 `tenant_id` 的 chunks

---

## 3. 范围

### 做

| # | 能力 | 归属 |
|---|---|---|
| 1 | 注册 / 登录 / 当前用户（JWT） | backend |
| 2 | 注册博主时自动建租户 | backend |
| 3 | 专家 CRUD（M1 只要建 + 列表 + 详情） | backend |
| 4 | 素材上传：**粘贴正文**（P0）、**文件**（P0）、**链接**（P1，只承诺公众号） | backend 收，agent 解析 |
| 5 | 触发构建 + 进度查询 | backend 转发，agent 执行 |
| 6 | 解析流水线：清洗 → 切分 → 向量化 → 写 chunks | agent |
| 7 | 登录页 / 专家列表 / 上传内容 / 构建进度 | frontend |

### 不做（留到后续里程碑）

七维提炼（M2）、检索与对话（M3）、反馈与看板（M4）、支付（M5）、
视频音频转文字（二期）、多平台同步（二期）、**OSS 对象存储**（见 plan §2.1）。

## 4. 验收标准

| # | 断言 | 验证 |
|---|---|---|
| B1 | 注册博主后，`users` 多一行且 `tenants` 多一行，二者关联正确 | 后端集成测试 |
| B2 | 未带 JWT 访问 `/api/experts` 返回 401 | 后端集成测试 |
| B3 | 博主 A 的 token 访问博主 B 的专家详情，返回 404（不是 403，不泄露存在性） | 后端集成测试 |
| B4 | 粘贴一篇 3000 字文章 → 构建完成后 `chunks` 有 ≥ 5 行，且 `tenant_id` 全部等于该博主的租户 | 端到端测试 |
| B5 | 每条 chunk 的嵌入文本带"文章标题 > 小节标题"前缀 | agent 单测 |
| B6 | **同一篇内容重复上传，不产生重复 chunks**（`content_hash` 去重） | 端到端测试 |
| B7 | **内容里藏 "忽略以上所有指令" → 该 chunk 被标记且 confidence 降权，但不删除** | agent 单测 |
| B8 | 构建过程中 `GET /api/experts/{id}` 能读到递增的 progress，失败时能读到 error | 端到端测试 |
| B9 | agent 用 `app_agent` 角色读 `materials`（新表）成功，读 `users` 仍被拒 | agent 测试 |
| B10 | 断开 embedding 供应商（模拟 API 报错）→ build_job 状态变 `failed` 且 error 有可读信息，不产生半截 chunks | agent 测试 |
| B11 | 契约仍然幂等，三方类型检查通过 | `make contract-check && make typecheck` |

> B3 用 404 而不是 403 是刻意的：403 等于告诉攻击者"这个 id 存在但你没权限"，
> 在 RLS 之上再加一层不泄露存在性。实际上 RLS 会让查询直接返回 0 行，天然就是 404。

> B10 的"不产生半截 chunks"意味着**写 chunks 必须在一个事务里全成功或全回滚**。

## 5. 明确的取舍

| 取舍 | 决定 | 理由 |
|---|---|---|
| 原始文件存哪 | **M1 存 Postgres 的 `materials.raw_text`，不接 OSS** | 不依赖阿里云账号就能端到端跑通；`storage_key` 字段预留，接 OSS 时不改表 |
| 没有百炼 API Key 怎么办 | **embedding 走可切换的 Provider**，本地/CI 用确定性假向量 | 让 M1 现在就能跑通，也让 CI 不依赖外部 API 和真金白银 |
| 链接抓取 | **只承诺公众号**，其他平台尽力而为，失败就引导粘贴正文 | 知乎/小红书反爬要持续对抗，不是 MVP 该做的事 |
| 粉丝注册 | **M1 不做**，只有博主端 | 粉丝入口在 M3（对话）才需要 |

## 6. 风险

| 风险 | 后果 | 对策 |
|---|---|---|
| 切分质量差 | 后面 M3 检索不到，但要到 M3 才暴露 | B5 把"标题路径前缀"变成硬性验收；切分参数集中在一处配置 |
| 向量化烧钱 | 博主一次传 100 篇，成本失控 | M1 就加单次构建的 chunk 数上限 + 内容去重 |
| 长任务失败后状态卡住 | 进度条永远停在 40% | ARQ 任务异常必须写回 `build_jobs.status = failed`（B10） |
| 注入内容混入 | M3 生成时被污染 | B7 在入库阶段就标记降权（防注入 4 条的第 1、4 条） |
