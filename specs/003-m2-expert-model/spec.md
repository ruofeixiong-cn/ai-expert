# M2 · 七维专家模型 —— 规格（Spec）

**上游**：`docs/AI专家平台-MVP产品文档.md` §7（七维数据结构）、§8（AI 生成 + 博主确认）、§10.1（时序）
**依赖**：M1（内容入库）已完成
**下游**：M3 对话

---

## 1. 这一步要证明什么

> **AI 能从博主的文章里提炼出一份"像他"的思维说明书，博主看完只需要改，不需要写。**

M1 把内容变成了可检索的切片 —— 但那只是"知识"这一层（五层能力的第 1 层）。
M2 要产出的是**专家模型**：这个人怎么说话、信什么、怎么分析、什么不能答。
没有它，AI 专家就只是一个"会背书的搜索器"。

### 这一步同时是产品的信任时刻

产品文档 §8.5 说得很直接：这是博主的"第一印象"时刻，值得花最多心思打磨 ——
**生成得准，博主会感叹"它真的懂我"；生成得离谱，他会当场关掉页面。**
所以本里程碑的成败不只看"能不能生成"，更看"生成的东西敢不敢给博主看"。

---

## 2. 最大的坑：AI 会过度推断

产品文档 §8.3 点名了这个风险：**AI 会把博主从没表达过的观点、立场脑补出来。**

对一个要拿来代表真人说话的产品，这是信任崩塌级别的问题 ——
博主看到"我"说了一句自己根本不认同的话，比看到"我不知道"糟糕一百倍。

### 工程解法：每个条目必须带证据

七维里的每一条都要带 `evidenceChunkIds`（它来自哪几个知识切片）。

- **有证据** → 正常展示
- **无证据 / 证据 ID 不存在于本次输入** → **标红**，明确告诉博主"这条是 AI 推断的，原文里没有"

这比"低置信度标红"更硬：置信度是模型的**自评**（它对自己脑补的内容也可能很自信），
而证据链是**可验证的事实**。

## 3. 七维的三种待遇（对应产品文档 §8.2）

| 维度 | AI 可靠度 | 处理方式 | 前端呈现 |
|---|---|---|---|
| ① Persona 怎么说话 | 🟢 高 | 自动生成 | 默认折叠，默认通过 |
| ② Knowledge 知道什么 | 🟢 高 | 自动生成 | 默认折叠，默认通过 |
| ③ Beliefs 相信什么 | 🟡 中（**最易脑补**） | 生成 + **重点确认** | 默认展开，逐条要证据 |
| ④ Methodology 怎么分析 | 🟡 中（易遗漏） | 生成 + 博主补充 | 默认展开 |
| ⑤ Decision Rules 怎么决策 | 🔴 低（常是隐性） | AI 先猜 + **博主重点补充** | 默认展开，鼓励新增 |
| ⑥ Boundaries 拒绝回答 | 🔴 低（禁区隐性） | **平台给三层默认模板 + 博主确认** | **必须确认才能上线** |
| ⑦ Examples 真实样本 | ⚪ 只能抽取 | 从原文抽真实问答对，**绝不编造** | 展示原文出处 |

> **Boundaries 不让 AI 猜。** 产品文档 §7.2 把它拆成三层（冒充风险 / 专业建议风险 / 立场越界），
> 这三类是**通用的合规风险**，不是博主的个人特征。让 AI 从文章里"提炼禁区"既提炼不出来，
> 也会给博主一种"平台已经帮我想好了"的错觉。所以由平台给默认模板，博主在其上增删。

## 4. 范围

### 做
1. 构建流水线增加"提炼七维"阶段，产出**草稿**
2. 草稿与定稿分离：草稿由 agent 写，定稿由博主确认后 backend 写
3. 分块确认接口：一次确认一个维度
4. 上线接口：生成分享短链，状态置 online
5. 单独重新生成七维（不重新向量化，省钱）
6. 前端分块确认页 —— 本里程碑最值得打磨的界面

### 不做
四路分流（M1 全部走 knowledge，分流是三期的事）、对话（M3）、
人格深化 / 决策框架层（三期）、多版本历史与回滚。

## 5. 验收标准

| # | 断言 | 验证 |
|---|---|---|
| C1 | 构建完成后产出七维草稿，七个维度都存在（可以为空数组） | 端到端 |
| C2 | **每个条目的 `evidenceChunkIds` 要么为空，要么全部真实存在于该专家的 chunks** | agent 单测 + 端到端 |
| C3 | 模型编造的 chunk id 被过滤掉，该条目降级为"无证据"而不是报错 | agent 单测 |
| C4 | Boundaries 恒为平台三层默认模板，不由 AI 生成 | agent 单测 |
| C5 | Examples 的问答对能在原文里找到出处（`evidenceChunkIds` 非空），否则丢弃 | agent 单测 |
| C6 | 分块确认只影响被提交的那一个维度，其余不变 | 后端测试 |
| C7 | **Boundaries 为空时不允许上线**，返回可读原因 | 后端测试 |
| C8 | 上线后生成全局唯一的 `share_slug`，重复上线不改变它 | 后端测试 |
| C9 | 跨租户确认 / 上线他人的专家返回 404 | 后端测试 |
| C10 | 重新生成七维不触发重新向量化（chunk 数与 embedding 不变） | 端到端 |
| C11 | 提炼服务失败时，已有的草稿不被清空，job 置 failed 且原因可读 | agent 单测 |

> C10 是省钱条款：博主会反复重新生成七维直到满意。每次都重新向量化的话，
> 一篇长文来回几次就是真金白银。

---

## 6. 风险

| 风险 | 后果 | 对策 |
|---|---|---|
| AI 脑补博主立场 | 信任崩塌 | C2/C3 的证据链 + Beliefs 默认展开逐条确认 |
| 切片太多喂不进模型 | 提炼失败或成本失控 | 按材料均匀采样，限定字符预算 |
| 结构化输出解析失败 | 整个构建失败 | Pydantic AI 校验 + 一次带错误回喂的重试；仍失败则保留旧草稿（C11） |
| 博主嫌确认麻烦直接跳过 | Boundaries 形同虚设 | 只对 Boundaries 设硬门槛，其余"默认通过" |
