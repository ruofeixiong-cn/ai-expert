## 当前状态

### W4 的结论：`RERANK_MIN_SCORE` 0.05 → 0.15

一次召回扫出来的曲线（真实模型，26 道题）：

| 阈值 | covered 召回保留 | uncovered 正确拦下 |
|---|---|---|
| 0.05 | 14/14 100% | 2/12 **17%** ← 旧值 |
| 0.12 | 14/14 100% | 10/12 83% |
| **0.15** | **14/14 100%** | **12/12 100%** ← 新值 |
| 0.20 | 12/14 86% | 12/12 100% |

分数分布：**covered 最低 0.1874，uncovered 最高 0.1459，间隔只有 0.0415。**

### 改动前后（同一批题、同一份语料）

| | 改之前 | 改之后 |
|---|---|---|
| covered 召回命中 | 14/14 | 14/14 |
| covered 要点覆盖 | 14/14 | 14/14 |
| **uncovered 编造** | **2/12** | **0/12** |
| uncovered 正确拒答 | 12/12（闸门拦 2，模型自己承认 10） | 12/12（**闸门拦 12**） |
| prompt tokens/题 | 1211 | **628**（−48%） |
| completion tokens/题 | 142 | 87（−39%） |
| 延迟 | 3.66s | **2.20s**（−40%） |

`make eval-diff`：

```

2 处变化
```

**能力一点没少，成本掉了一半，编造清零。**
原来那 10 道题每次都要白跑一次生成模型，还顺手给了模型夹带世界知识的机会 ——
实测漏了 2 道（"私募门槛 100 万"、国债逆回购的操作细节）。
这些都不是博主写过的东西。

顺带收紧了防注入：投毒切片被降权到 0.2，现在需要 **0.75** 的 rerank 分数
才挤得进来（原来 0.25），而整个黄金集里最高的一条真实分数是 0.9262。

### 这一步找出来的三件事

| # | 是什么 | 怎么发现的 |
|---|---|---|
| 1 | 🔴 **尺子自己的刻度是错的** | 「要点覆盖 35.7%」看着像 prompt 很差，实际是黄金集把同义词写成了一个组 —— 而组内是 AND，等于要求答案同时说出「两成」「20%」「百分之二十」。修好后是 **100%** |
| 2 | 🔴 闸门 0.05 定得太低 | 阈值扫描：0.05 只拦下 17% 的无关问题，而 0.15 拦 100% 且召回一条不掉 |
| 3 | 🟠 must_not 会误伤正确的拒答 | 模型拒答时会顺口列举话题词（"没提过黄金…也没给过任何比例建议"），撞上 `[[黄金, 比例, 建议]]`。规则要瞄准**具体数字**，不是话题 |

第 1 条最值得记：**尺子有刻度错误的时候，它读出来的每一个数都是错的**，
而且读数看起来完全合理 —— 35.7% 不像 bug，像一个需要去调 prompt 的信号。
差一点就去改 prompt 了。`tests/test_eval_harness.py` 现在拦着这个错误再犯。
